# FlashAttention forward on dav-2201

`910b.py` builds a generic and a pipeline variant from the same online-softmax
step. Pass `variant="generic"` for a serial KV loop or `variant="pipeline"` for
ordinary automatic `T.Pipelined`. Both use the numerical and input contract
below. The CPU oracle models block rounding; performance comparisons require
separate evidence from the selected hardware and installed Torch NPU version.

Inputs use contiguous `Q[B,Hq,Sq,D]`, `K[B,Hkv,Sk,D]`, and `V[B,Hkv,Sk,D]`.
Output is `O[B,Hq,Sq,D]`. Dimensions are positive, `Hq` is divisible by `Hkv`,
and consecutive groups of `Hq/Hkv` query heads share a KV head. Operand and
output dtype is FP16 or BF16. `D`, `block_q`, and `block_kv` are multiples of 16;
`Sq` and `Sk` may have tails. The expression supports neither dropout nor an
attention bias or arbitrary padding mask.
Inputs after operand rounding and the resulting FP32 scores must be finite.
Negative infinity used for masking and initial running maxima is part of the
algorithm. The CPU oracle diagnoses nonfinite inputs or score overflow.

For causal attention, key index `j` is visible to query index `i` when
`j <= query_start + i`. `query_start` is nonnegative and
`query_start + Sq <= Sk`; the first KV block therefore contains a visible key
for every query. For noncausal attention all `Sk` keys are visible. The default
scale is `1 / sqrt(D)` and a supplied scale must be finite.

Scores, running maximum, denominator, and output accumulation use FP32. For
each KV block the algorithm updates

```
m_next = max(m, reduce_max(scores))
alpha = exp(m - m_next)
p = exp(scores - m_next)
l = alpha * l + reduce_sum(p)
o = alpha * o + cast_to_operand_dtype(p) @ V_block
```

It finally writes `cast_to_operand_dtype(o / l)`. The denominator sums FP32
probabilities, while the second Cube GEMM consumes rounded FP16/BF16
probabilities. Changing `block_kv` can change these rounding points. Generic
and pipeline variants with the same parameters have the same numerical
contract. `attention_reference` models these operations on CPU; it does not
model native instruction error or certify device execution.

The pipeline variant exposes `alpha * o` as a separate FP32 Parallel task
before exporting P. The later FP32 add completes the same output epoch after
PV is ready. This lets the scheduler distinguish independent rescaling from
the operation that consumes PV; the generic variant keeps the complete update
after PV. Both retain the same multiply and add rounding points.

The Torch NPU reference uses `npu_fusion_attention(..., head_num=Hq,
input_layout="BNSD", sparse_mode=0, keep_prob=1)`, original `Hkv` K/V heads,
and a dense bool mask where `True` excludes a key. Causal exclusion is exactly
`j > query_start + i`, with unrestricted pre/next windows. This avoids relying
on a sparse causal mode's alignment convention for rectangular inputs. Torch
computes the same attention function, but its internal block rounding can
differ from this explicit per-block P rounding; comparisons need declared
dtype tolerances rather than bitwise equality.

`FwdTiling` controls `block_q`, `block_kv`, and the automatic pipeline search
bound `max_stages`. Q stays in L1 across the KV loop; K and V are loaded once
per iteration. These cache and traversal choices live in the Python algorithm.
The compiler chooses issue order, stages and buffer versions under the target
capacity checks. A `max_stages` value is a search bound rather than a promised
stage count or performance estimate.

The kernel carries `qrows = min(block_q, Sq - query_base)` on the score, P, PV,
and output copy regions. All connected UB buffers retain one logical row
capacity until ownership lowering gives each AIV its private rows. The GM
handoff owns group isolation and L1 tail initialization. The user does not
allocate reduction scratch, encode two AIV offsets, or issue synchronization.
The running maximum updates through an ordinary FP32 tile copy over `qrows`;
it preserves the stored bits and exposes the next iteration's state dependency.
The backend lowers this state copy to a native bit-preserving UB operation,
with the same bounded element count used for a dynamic tail or an empty owner.
Masking uses ordinary selection, rescaling uses ordinary `max` and `exp`, and
normalization uses ordinary division. There is no combined softmax primitive.

Before performance comparison, the integration must pass CPU IR/codegen checks,
CANN offline compilation, and a small same-card correctness comparison. Compare
both variants against the same installed Torch NPU attention implementation,
with matching layout, GQA, causal offset, scale, dtype and output contract.
